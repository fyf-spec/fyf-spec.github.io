# 计算机网络 Cheatpaper（Ch1-6）

## 1. 概述

### 互联网与协议

**互联网定义**：构成角度：端系统/主机、通信链路、分组交换设备、协议；核心是互联异构网络。服务角度：为分布式应用提供通信服务，提供 socket/API，底层尽力传输。
**协议**：报文格式、交换顺序、事件动作；本质是通信实体之间的规则集合。例：HTTP、DNS、TCP、IP、ARP、BGP。
**网络边缘**：端系统运行应用，网络核心不跑用户应用。C/S：服务器常开、固定 IP、客户端主动。P2P：peer 既下载又上传，自扩展但管理难。
**网络核心**：互连路由器，负责逐跳转发分组。转发=本地查表选输出口，数据平面动作；路由=全网路径计算，控制平面动作。
**网络的网络**：接入 ISP、区域 ISP、Tier-1、IXP、内容提供商网络；由商业关系和策略互联。全互连 $O(N^2)$ 不可扩展。
**标准**：IETF 制定开放协议标准，RFC 是主要公开文档形式；开放标准保证不同厂商设备互操作。

### 接入网与物理介质

**接入网**：端系统到第一跳边缘路由器；决定用户最后一公里速率、时延和共享程度。住宅、机构、移动、数据中心接入。
**HFC**：混合光纤同轴，多个家庭共享同轴段，数据和电视信号频分复用；下行通常高于上行，受共享用户数影响。
**DSL**：复用已有电话线，数据和语音不同频段，连接中心局 DSLAM；通常家庭到中心局为专线，速率受距离影响。
**FTTP**：光纤到户/楼，高带宽、长距离、抗电磁干扰；适合高吞吐接入和未来扩展。
**机构接入**：以太网 + WiFi + 机构路由器，常见校园/企业网；内部用交换机/AP 汇聚，出口连接 ISP。
**移动/无线**：WiFi 覆盖几十米、低成本局域接入；蜂窝广域移动覆盖；卫星覆盖广但传播时延大。
**引导型介质**：双绞线、同轴电缆、光纤；信号沿固体介质传播。光纤高速、低误码、抗电磁干扰，适合骨干和长距离。
**非引导型介质**：无线电、微波、卫星；信号在空间传播。部署灵活，但受反射、遮挡、噪声、干扰和共享介质影响。

### 分组交换、时延、吞吐

**分组交换**：消息切分为分组，按需共享链路，适合突发数据；依赖统计复用。代价是排队、拥塞、丢包和时延不确定。
**存储转发**：路由器完整收到一个分组后才能转发第一个 bit；每跳都产生传输时延。单链路传输时延 $L/R$。
**电路交换**：通信前预留端到端资源；FDM/TDM；性能稳定、类似保证带宽，但连接空闲时资源也不能给别人用。
**统计复用**：多用户不同时活跃时共享链路，提高平均利用率；若同时活跃用户过多，队列增长并产生拥塞。
**节点时延**：$d_{nodal}=d_{proc}+d_{queue}+d_{trans}+d_{prop}$；排队时延最难预测，取决于瞬时突发流量。
**传输时延**：$d_{trans}=L/R$，把全部 bit 推入链路；与分组长度和链路速率有关，提高带宽会降低它。
**传播时延**：$d_{prop}=d/s$，信号在介质中传播；与距离和传播速度有关，提高带宽不一定降低它。
**流量强度**：$La/R$ 表示到达工作量/服务能力；接近 1 时排队时延暴涨，大于 1 时队列持续增长并丢包。
**丢包**：缓冲区满导致丢弃；后续可能链路层重传、TCP 端到端重传，或 UDP/实时应用直接容忍。
**吞吐量**：端到端比特交付速率，分瞬时和平均；瓶颈链路决定吞吐，无核心瓶颈约 $\min(R_s,R_c)$。
**共享瓶颈**：n 条连接公平共享核心链路 R 时，每条吞吐约 $\min(R_s,R_c,R/n)$；现实还受拥塞控制和 RTT 影响。
**traceroute**：TTL 递增探测路径；中间路由器 TTL 归零后返回 ICMP TTL expired，终点常返回 port unreachable 作为停止信号。

### 分层与封装

**分层原因**：显式结构、模块化、易调试、易标准化、内部实现可替换；代价是层间功能可能重复。
**服务/协议/接口**：服务=下层给上层能力；协议=同层实体报文规则；接口=上层调用下层方式，如 socket API。
**TCP/IP 五层**：应用 message，传输 segment，网络 datagram，链路 frame，物理 bit；每层只关注相邻层服务。
**封装**：应用数据加 $H_t$、$H_n$、$H_l$；每层添加并解释本层首部，接收端逐层解封装。
**路由器处理**：通常处理到网络层：拆链路帧、查 IP 首部、选择下一跳、重新封装链路帧；不看应用数据。
**OSI 七层**：比 TCP/IP 多表示层和会话层；互联网通常把加密、压缩、序列化、会话管理放在应用层或库中。

## 2. 应用层

### 应用架构与传输服务

**应用层位置**：运行在端系统，不运行在网络核心；网络核心只负责转发，保持简单和可扩展。
**C/S 架构**：服务器常开、固定 IP、部署在数据中心；客户端主动请求、间歇在线、动态 IP，客户端之间通常不直接通信。
**P2P 架构**：peer 既请求又服务；新 peer 带来下载需求也带来上传能力，自扩展强；难点是 churn、安全、激励、发现。
**进程通信**：socket 是应用与传输层的门。IP 定位主机，端口定位进程；同一主机多个进程靠端口区分。
**应用协议内容**：报文类型、语法、语义、交互规则；决定请求/响应如何组织以及错误如何处理。
**服务需求**：数据完整性、吞吐量、时延、安全性；文件/邮件重完整性，实时音视频更重时延并可容忍少量丢失。
**TCP**：可靠、有序、流量控制、拥塞控制、连接建立；适合 Web、邮件、文件传输；不保证最低速率/时延，不内置加密。
**UDP**：无连接、低开销、无握手，应用可自控时延和可靠性；不可靠、不流控、不拥塞控制，适合 DNS、实时、QUIC。
**TLS**：位于应用和 TCP 之间，提供加密、完整性、认证；HTTPS = HTTP over TLS over TCP。
**端口**：HTTP 80，HTTPS 443，SMTP 25，DNS 53，FTP 20/21，SSH 22，IMAP 143，POP3 110；熟记用于协议识别。

### HTTP、Cookie、缓存

**HTTP**：TCP 80，请求/响应，无状态；服务器不因协议本身记住历史请求，简化服务器但需要 Cookie 支持状态。
**非持久 HTTP**：每个对象一个 TCP 连接；响应时间约 $2RTT+$文件传输时间，多个对象开销大。
**持久 HTTP**：多对象复用 TCP 连接，减少 RTT、握手和操作系统连接开销；HTTP/1.1 默认使用。
**流水线**：连续发送请求，不等前一个响应；减少等待，但 HTTP/1.1 仍可能应用层队头阻塞。
**方法**：GET 请求对象，POST 在实体主体提交数据，HEAD 只返回头用于检查元信息，PUT 上传对象到指定路径。
**状态码**：200 成功，301 永久移动，304 缓存未修改，400 请求格式错，404 对象不存在，500 服务器错，505 版本不支持。
**Cookie 组成**：`Set-Cookie`、`Cookie`、浏览器 Cookie 文件、服务器后端数据库；客户端带标识，服务器用标识查状态。
**Cookie 用途**：登录保持、会话、购物车、个性化推荐；也可能被第一方/第三方跟踪用户，带来隐私问题。
**Web 缓存**：代理服务器。命中直接返回，未命中请求源站并保存副本；可部署在浏览器、机构、ISP、CDN。
**缓存原因**：降低响应时间、减少接入链路流量、减轻源站压力；高命中率能显著降低排队时延。
**条件 GET**：`If-Modified-Since` + `Last-Modified`；未变 304 无主体，节省带宽；已变 200 + 新对象。
**HTTP/2**：单 TCP 多流复用、帧、优先级、服务器推送；缓解 HTTP 层 HOL，但 TCP 丢包仍阻塞字节流。
**HTTP/3**：QUIC over UDP；可靠性、拥塞控制、加密、多流放在 QUIC 中，减少 TCP 层 HOL，便于协议快速演进。

### 邮件、DNS、P2P、视频、Socket

**邮件组成**：用户代理 UA、邮件服务器、邮箱、发送队列、SMTP、访问协议；发送和读取是不同协议角色。
**SMTP**：TCP 25，邮件服务器间推送邮件，ASCII 命令/响应；发送方主动连接接收方邮件服务器。
**SMTP 命令**：`HELO/EHLO` 握手，`MAIL FROM` 发件人，`RCPT TO` 收件人，`DATA` 正文，`QUIT` 关闭。
**SMTP vs HTTP**：SMTP 推送邮件，HTTP 拉取对象；二者都用 TCP 和文本命令/状态码，但对象组织方式不同。
**IMAP**：邮件保存在服务器，支持文件夹、检索、删除、多端同步；适合多设备邮箱。
**POP3**：简单拉取邮件，常用于下载后本地管理；功能比 IMAP 简单。
**DNS**：分布式层次数据库，应用层协议；通常 UDP 53，必要时 TCP，避免集中式 DNS 的单点故障和瓶颈。
**DNS 服务**：主机名到 IP、CNAME 别名、MX 邮件服务器、负载分配；一个名字可对应多个 IP。
**DNS 层次**：本地 DNS、根、TLD、权威 DNS；本地 DNS 是查询第一站并缓存，不严格属于层次结构。
**迭代查询**：每层返回下一层线索，由本地 DNS 继续问；高层服务器负担较小。
**递归查询**：被查询服务器代替请求者继续查到底；方便客户端，但高层服务器通常不愿大规模递归。
**DNS 缓存**：TTL 控制有效期；降低解析时延和服务器负载，但 TTL 内可能返回旧地址。
**RR 类型**：A：主机到 IPv4；NS：域到权威服务器；CNAME：别名到规范名；MX：域到邮件服务器。
**DNS 安全**：DDoS、查询拦截、虚假响应、缓存投毒；DNSSEC 提供来源认证和消息完整性。
**BitTorrent**：tracker、peer 列表、块交换、rarest first、tit-for-tat、churn；利用 peer 上传能力分摊服务器压力。
**rarest first**：优先请求副本少的块，提高块分布均匀性，避免某些块因 peer 离开而消失。
**tit-for-tat**：优先给当前给自己最高下载速率的 peer 上传，周期性乐观解阻塞；激励上传并探索新邻居。
**DASH**：视频切块，多码率，manifest，客户端按带宽和缓冲选码率；核心是客户端自适应，避免卡顿。
**CDN**：内容副本靠近用户；减少长路径传输、时延、源站压力；关键问题是内容放置和用户重定向。
**UDP socket**：`SOCK_DGRAM`，`sendto/recvfrom`，每次发送指定目的地址；保留报文边界。
**TCP socket**：`SOCK_STREAM`，`connect` 触发握手；服务器 `accept` 产生 connection socket；提供可靠字节流。

## 3. 传输层

### 服务、复用分解、UDP

**传输层**：进程到进程逻辑通信；网络层是主机到主机，传输层通过端口把数据交给正确应用。
**多路复用**：发送端从多个 socket 收集数据，加传输层首部交给 IP；把多个应用数据流合并到网络层。
**多路分解**：接收端按首部字段把 segment 交给正确 socket；依赖端口号和连接标识。
**UDP 分解**：目的 IP + 目的端口；多个发送方可进入同一个 socket，服务器容易用一个 socket 接收多客户。
**TCP 分解**：源 IP、源端口、目的 IP、目的端口四元组；每条连接一个 socket，支持同端口多连接并发。
**UDP 特点**：无连接、不可靠、无序、8 字节首部、无拥塞控制；不维护连接状态，首部和处理开销小。
**使用 UDP 原因**：无握手、低开销、应用可控制时延和可靠性，适合 DNS、SNMP、实时音视频、QUIC；但可能不公平。
**UDP 首部**：source port、destination port、length、checksum；字段少，体现轻量设计。
**UDP 校验和**：16 bit 反码求和，覆盖 UDP 首部/数据和 IP 伪首部；轻量检错但可能漏检。

### rdt 原理

**rdt 目标**：在不可靠信道上向上层提供可靠交付；关键是不交付损坏数据、不漏数据、不重复交付。
**checksum**：检测比特错误；接收方据此判断分组是否损坏，但不能纠正错误。
**ACK/NAK**：ACK 表示正确收到，NAK 表示损坏需重发；属于接收方反馈机制。
**序列号**：区分新分组和重传旧分组，防止 ACK 丢失或超时重传导致重复交付。
**定时器**：处理数据包或 ACK 丢失；发送后启动，超时就假设丢失并重传。
**窗口**：允许多个分组在途，提高链路利用率；窗口大小控制未确认数据量。
**缓冲区**：保存乱序分组，等待缺口补齐后按序交付；SR/TCP 需要，GBN 通常不用。
**rdt 1.0**：完全可靠信道，直接发送和交付；不需要差错检测、确认或重传。
**rdt 2.0**：信道可能比特错误；引入 checksum、ACK、NAK，但没有解决 ACK/NAK 损坏。
**rdt 2.1**：ACK/NAK 也可能损坏；引入 0/1 序号，接收方识别重复分组并避免重复交付。
**rdt 2.2**：无 NAK；用重复 ACK 表示仍期待某个序号，为 TCP 的重复 ACK 思想做铺垫。
**rdt 3.0**：信道可能丢包；发送后启动定时器，超时重传；序号处理延迟 ACK 和重复分组。
**停止等待**：简单，1 bit 序号足够；一次只允许一个分组在途，利用率 $U=(L/R)/(RTT+L/R)$，RTT 大时效率低。
**流水线协议**：多个分组同时在途；需要大序号空间、窗口、发送/接收缓存，使链路不空等 ACK。
**GBN**：累积 ACK，只按序接收，乱序丢弃；只给最老未确认分组计时，超时重传丢失点及之后全部分组。
**SR**：单独 ACK 和计时器，缓存乱序，只重传未确认分组；效率高但状态复杂，需避免序号回绕混淆。

### TCP 可靠传输与连接管理

**TCP 特性**：点对点、可靠有序字节流、全双工、面向连接、流水线、累积 ACK、流控、拥塞控制。
**TCP 首部**：端口、seq、ack、flags、rwnd、checksum、urgent pointer、options、data；首部承载可靠性和控制信息。
**flags**：SYN 建连，ACK 确认，FIN 关闭，RST 复位，PSH 推送，URG 紧急，ECE/CWR 用于 ECN。
**seq**：本段数据第一个字节编号；TCP 对字节编号而不是对段编号。
**ack**：期望收到的下一个字节编号，体现累积确认；ACK=n 表示 n 之前字节已收到。
**RTT 估计**：$EstimatedRTT=(1-\alpha)EstimatedRTT+\alpha SampleRTT$，$\alpha=0.125$；EWMA 平滑突发波动。
**RTT 偏差**：$DevRTT=(1-\beta)DevRTT+\beta|SampleRTT-EstimatedRTT|$，$\beta=0.25$；反映 RTT 抖动。
**超时间隔**：$TimeoutInterval=EstimatedRTT+4DevRTT$；重传样本通常忽略，避免 ACK 歧义污染估计。
**ACK 规则**：按序可延迟；乱序/缺口立即重复 ACK；补缺口立即 ACK，帮助发送方快速发现丢失。
**快速重传**：三个重复 ACK 触发，不必等待超时；适合单个段丢失但后续段到达的场景。
**流量控制**：保护接收方缓冲区；接收方通告 `rwnd`，防止发送方淹没接收缓存。
**流控公式**：$LastByteSent-LastByteAcked \le rwnd$；在途未确认字节不能超过接收方可用空间。
**三次握手**：SYN seq=x；SYNACK seq=y ack=x+1；ACK ack=y+1；双方同步初始序号。
**握手原因**：确认双方可通信，初始化序号，避免旧重复连接请求导致半开连接或重复数据。
**连接关闭**：每个方向独立关闭；FIN 表示本方向不再发送，对方 ACK，另一方向仍可继续发送直到 FIN。

### 拥塞控制与 QUIC

**拥塞控制**：保护网络内部，防止路由器队列过长、丢包和重传浪费；根据丢包、重复 ACK、ECN 或时延推断拥塞。
**流控 vs 拥塞**：流控保护接收方缓冲区；拥塞控制保护网络链路和路由器队列。
**`cwnd`**：拥塞窗口，限制发送方在途数据量；由发送方根据网络反馈动态调整。
**有效窗口**：$\min(cwnd,rwnd)$；发送同时受网络拥塞和接收方缓存限制。
**发送速率**：约 $cwnd/RTT$；RTT 越大，同样窗口下速率越低。
**AIMD**：拥塞避免每 RTT 约 +1 MSS；检测丢包后乘性减小，形成锯齿形窗口变化并趋向公平。
**慢启动**：初始 `cwnd=1 MSS`，每 ACK 增加 1 MSS，每 RTT 近似翻倍；名字慢但增长指数级。
**`ssthresh`**：`cwnd<ssthresh` 慢启动；`cwnd>=ssthresh` 拥塞避免；丢包时 `ssthresh=cwnd/2`。
**Reno**：三次重复 ACK 后快速重传/快速恢复，窗口通常减半；认为网络仍能传递后续段。
**Tahoe/超时**：超时代表更严重拥塞或 ACK 反馈中断，窗口降到 1 MSS 并重新慢启动。
**TCP 吞吐**：窗口在 $W/2$ 到 $W$ 锯齿，平均吞吐约 $3W/(4RTT)$；高带宽长 RTT 需要大窗口和低丢包。
**公平性**：理想 K 条 TCP 共享 R 得 $R/K$；UDP 不退让、多 TCP 并行连接、RTT 差异会破坏公平。
**CUBIC**：记录 $W_{max}$，远离旧峰值快增长，接近旧峰值慢增长；适合高速长距离和大 BDP 链路。
**延迟型控制**：用 $RTT_{min}$ 估计无拥塞状态，比较实际吞吐和无拥塞吞吐；目标是管道刚好满但队列不过满。
**ECN**：路由器标记拥塞而非丢包；接收方 ECE 通知，发送方 CWR 响应并降速，提前避免丢包。
**QUIC**：UDP 上实现可靠、拥塞、加密、连接、多流；建连快，减少 TCP HOL，用户态实现便于部署演进。

## 4. 网络层：数据平面

### 服务模型、路由器、转发

**网络层**：主机到主机通信；负责把 IP 数据报从源主机经多跳送到目的主机。
**Internet 服务模型**：Best effort：不保证交付、时限、顺序、最小带宽；可靠性由传输层或应用层补充。
**数据平面**：每个分组的本地线速转发；动作频繁，通常由硬件快速完成。
**控制平面**：计算路径、生成转发表/流表；时间尺度较慢，由路由协议或 SDN 控制器完成。
**路由器组成**：输入端口、交换结构、输出端口、路由处理器；数据平面和控制平面在设备内协作。
**输入端口**：物理/链路处理、转发表查找、输入排队；要尽量在线速完成查表。
**交换结构**：内存、总线、互联网络/crossbar；目标是把分组从输入端口移到正确输出端口。
**输出端口**：缓存、调度、链路封装、物理发送；拥塞时常在输出队列排队。
**最长前缀匹配**：多条规则匹配时选择前缀最长者；otherwise 是默认路由，常用于 Internet 路由聚合。
**HOL blocking**：输入队首分组被目标输出端口阻塞，后续即使可去其他输出也无法前进。
**输出排队**：多个输入争同一输出端口时发生；缓存满会丢包，调度决定服务顺序。
**调度**：FIFO 简单，优先级区分业务但可能饥饿，RR 公平轮转，WFQ 按权重保障带宽。
**bufferbloat**：缓存过大导致排队时延过高；吞吐不一定差，但交互应用体验变差。

### IP、地址、DHCP、NAT、IPv6

**IPv4 首部**：version、hlen、ToS/DSCP/ECN、len、ID、flags、offset、TTL、protocol、checksum、src/dst；用于转发、分片、解复用。
**TTL**：每跳减一，防止环路；为 0 时丢弃并可触发 ICMP TTL expired。
**IPv4 checksum**：只校验首部；因 TTL 改变需要每跳重算，IPv6 删除该字段以简化处理。
**子网**：共享同一前缀、无需经过路由器即可互达的一组接口；通常由路由器接口分隔。
**CIDR**：`a.b.c.d/x`，任意长度前缀，支持路由聚合；解决传统分类地址浪费和路由表膨胀。
**特殊地址**：主机位全 0 表示子网；全 1 表示广播；具体可用性受上下文和配置影响。
**私有地址**：10/8，172.16/12，192.168/16；不能在公网直接路由，常配合 NAT 使用。
**DHCP 目的**：主机即插即用获取 IP、mask、gateway、DNS、lease；减少人工配置和地址冲突。
**DHCP DORA**：Discover 广播找服务器，Offer 提供地址，Request 请求租用，ACK 确认租约。
**DHCP 端口**：UDP 客户端 68，服务器 67；初始主机无 IP，常用广播通信。
**IP 分片**：MTU 触发；ID 相同，MF 表示更多分片，offset 单位 8 字节；分片丢失会导致整包重组失败。
**重组**：目的主机重组，路由器不重组；减少中间路由器状态和处理负担。
**NAT**：转换 `(内网IP,端口)` 与 `(公网IP,新端口)`，多个内网主机共享公网 IPv4；维护转换表。
**NAT 好处**：节省 IPv4、隐藏内部地址、内部改地址不影响外部、更换 ISP 时内部地址可不变。
**NAT 争议**：改写传输层端口，破坏端到端原则，外部主动连接内网困难，需要 NAT 穿越。
**IPv6**：128 bit 地址，固定 40B 首部，traffic class、flow label、next header、hop limit；地址空间巨大。
**IPv6 简化**：无首部校验和，无路由器分片，扩展功能用扩展头部；提高路由器转发效率。

### 通用转发

**通用转发**：match + action，不只按目的 IP 转发；可统一表达路由、防火墙、交换、NAT 等行为。
**匹配字段**：入端口、MAC、EtherType、VLAN、源/目的 IP、协议号、TCP/UDP 端口；跨多层字段匹配。
**动作**：转发、丢弃、修改头部、封装后发控制器；支持策略控制和流量工程。
**OpenFlow 流表**：Match、Action、Priority、Stats；优先级解决多规则同时匹配，统计用于管理和控制。
**统一描述**：路由器=目的 IP 最长前缀；防火墙=地址/端口允许或拒绝；交换机=目的 MAC；NAT=地址端口改写。
**中间盒**：NAT、防火墙、IDS、负载均衡器、缓存；增强安全/性能/管理，但冲击端到端原则和协议透明性。

## 5. 网络层：控制平面

### 路由算法

**路由图抽象**：节点=路由器，边=链路，代价=跳数/带宽/时延/拥塞；路由就是找低代价路径。
**目标**：正确、简单、健壮、稳定、公平、最优；实际协议常在最优性、稳定性和开销之间折中。
**分类**：全局 vs 分布式，静态 vs 动态，集中式 vs 迭代分布式；LS 是全局，DV 是分布式。
**LS 流程**：邻居发现、测链路代价、组装 LS 分组、可靠泛洪、Dijkstra；每台路由器得到相同拓扑图。
**LS 特点**：每台路由器获得全拓扑；收敛较快；有泛洪和计算开销，代价随负载变化可能振荡。
**Dijkstra 状态**：$N'$ 已确定集合，$D(v)$ 当前估计，$p(v)$ 前驱；最终形成最短路径树。
**Dijkstra 松弛**：$D(v)=\min(D(v),D(w)+c(w,v))$；不断用新确定节点改进邻居路径估计。
**DV 思想**：只和邻居交换距离估计，用 Bellman-Ford 更新；不需要知道完整拓扑。
**Bellman-Ford**：$D_x(y)=\min_v\{c_{x,v}+D_v(y)\}$；最小值对应下一跳邻居。
**DV 特点**：迭代、异步、分布式、自终止；无变化时不再持续发送更新。
**DV 风险**：路由环路、无穷计数；链路代价下降传播快，失效或代价上升传播慢。
**毒性逆转**：经邻居到达的路径向该邻居通告为无穷大，缓解两节点环路但不能解决所有环路。
**LS vs DV**：LS=全局拓扑+泛洪+Dijkstra，错误状态影响广；DV=邻居距离+BF，可能慢收敛和环路。

### AS、RIP、OSPF、BGP

**AS**：自治系统；层次化解决规模问题和管理自治问题，每个 AS 可独立选择内部路由策略。
**AS 内路由**：IGP，关注性能、收敛、资源利用；例 RIP、OSPF、IS-IS，通常由同一组织管理。
**AS 间路由**：EGP，事实标准 BGP；关注策略、商业关系、可扩展性，性能不是唯一目标。
**RIP**：DV，跳数指标，15 最大，16 不可达，约 30s 通告，UDP，毒性逆转；简单但规模和收敛受限。
**OSPF**：LS，AS 内泛洪，直接运行在 IP 上，Dijkstra，支持认证和区域层次；比 RIP 更适合大型 AS。
**OSPF 区域**：本地区域、骨干区域、区域边界路由器 ABR、AS 边界路由器 ASBR；区域化减少泛洪范围。
**BGP**：路径矢量协议，通过 TCP 交换前缀可达性和属性；把互联网各 AS 粘在一起。
**eBGP**：不同 AS 的网关路由器之间交换可达性；用于跨域通告前缀。
**iBGP**：同一 AS 内传播从外部学到的路由；让内部路由器知道可选出口。
**AS-PATH**：到达前缀经过的 AS 序列；用于防环、策略过滤和路径选择。
**NEXT-HOP**：到下一跳 AS 的具体边界路由器；AS 内还需靠 IGP 到达该出口。
**BGP 报文**：OPEN 建会话，UPDATE 通告/撤回，KEEPALIVE 保活，NOTIFICATION 报错关闭。
**BGP 选路**：local preference、最短 AS-PATH、最近 NEXT-HOP、其他规则；策略优先于纯最短路径。
**热土豆路由**：选离自己最近的出口，尽快把流量交给别的 AS；最小化本 AS 内部代价。

### SDN、ICMP、网络管理

**SDN 动机**：管理更简单，控制更灵活，接口更开放，便于创新；减少逐台设备手工配置错误。
**SDN 特征**：基于流转发，控制/数据分离，控制器在设备外，可编程控制；控制器逻辑集中但可分布实现。
**SDN 控制器**：控制应用、北向 API、网络状态管理、南向 API、交换设备；维护拓扑、统计和流表状态。
**OpenFlow 协议**：控制器和交换机之间的南向协议；负责实际安装、修改、删除流表项。
**OpenFlow 消息**：控制器到交换机：配置/流表/发包；交换机到控制器：packet-in/端口状态；对称：hello/echo。
**ICMP**：IP 错误报告和诊断，由 IP 携带；不负责可靠传输，而是辅助控制和排错。
**ping**：echo request type 8，echo reply type 0；测端到端连通性和 RTT。
**ICMP 常见类型**：type 3 不可达，type 11 TTL 过期，type 12 IP 头错误；traceroute 依赖 type 11。
**traceroute**：TTL 逐步增大；中间回 TTL expired，终点回 port unreachable；显示路径和每跳 RTT。
**SNMP**：manager/agent/MIB；request-response 和 trap；偏监测和简单变量管理。
**SNMP 报文**：GetRequest、GetNextRequest、GetBulkRequest、SetRequest、Response、Trap；支持读、批量读、设置和异常上报。
**MIB/SMI**：MIB 是变量库，SMI 是数据定义方式；对象用 OID 标识，常见为计数器和状态变量。
**NETCONF**：结构化配置管理；`get-config`、`get`、`edit-config`、`lock`、订阅通知；适合自动化配置。
**YANG**：NETCONF 数据建模语言，定义配置/状态数据结构、语义、约束；提高配置可验证性。

## 6. 链路层和局域网

### 链路层服务与差错检测

**链路层**：相邻节点之间传输数据报，单位 frame，通常在 NIC 实现；负责一跳交付，不负责端到端路径。
**服务**：帧封装、链路接入、MAC 寻址、单跳可靠、流控、差错检测/纠正；不同链路提供的服务不同。
**单跳可靠**：在高误码链路有用；低误码有线链路通常由端到端 TCP 补足，避免链路层 ACK 开销。
**奇偶校验**：单比特奇偶可检测单比特错；偶数个比特翻转可能漏检，适合简单低成本检测。
**二维奇偶**：可检测并纠正单比特错；通过行列定位错误位，开销更高。
**checksum**：便宜、软件实现简单，但检测能力弱于 CRC；常用于传输层端到端检错。
**CRC**：强检错，以太网和 WiFi 常用；特别擅长检测突发错误。
**CRC 原理**：数据 $D$、生成器 $G$、附加 $R$，使 $\langle D,R\rangle$ 可被 $G$ 整除；接收方余数非 0 检错。

### 多路访问

**目标**：单节点发送得 $R$，M 节点发送平均 $R/M$，去中心化，简单；核心是协调共享广播信道。
**分类**：信道划分、随机接入、轮流访问；分别对应预分配、冲突恢复、按序使用。
**TDMA/FDMA**：无冲突、分配清晰；低负载时空闲时隙/频段浪费，不适合强突发流量。
**轮询**：主节点轮流询问；无冲突但有轮询开销、等待延迟、主节点单点故障。
**令牌传递**：拿到令牌才能发；公平无冲突但有令牌开销、等待延迟和令牌丢失问题。
**纯 ALOHA**：无时隙，有帧就发；危险区 2 帧时间，最大效率 $1/(2e)\approx0.18$。
**时隙 ALOHA**：同步时隙，只能时隙开始发；成功概率 $Np(1-p)^{N-1}$，最大效率 $1/e\approx0.37$。
**CSMA**：先听后说；传播时延使远端节点可能还没听到对方就开始发送，因此仍会冲突。
**CSMA 策略**：1-持续空闲立即发，非持续忙则随机等，p-持续空闲时以概率 p 发。
**CSMA/CD**：有线以太网；边发边听，冲突即停，发送 jam 信号，减少冲突浪费时间。
**指数退避**：第 m 次冲突后选 $K\in\{0,\dots,2^m-1\}$，等待 $K\cdot512$ bit 时间；冲突越多退避范围越大。
**CSMA/CD 效率**：$1/(1+5t_{prop}/t_{trans})$；传播越短、帧越长越高，现代交换式全双工基本不用 CD。
**无线不用 CD**：发送时难检测冲突，且有隐藏站点、暴露站点；冲突常在接收端发生。
**CSMA/CA**：监听、IFS、随机退避、接收方 ACK、失败重传；目标是尽量避免冲突而不是边发边检测。
**DOCSIS**：下行 FDM 广播；上行 TDM 分配 + 随机竞争；MAP 指明上行时隙，混合调度和竞争。

### MAC、ARP、以太网、交换机

**MAC 地址**：链路层，本地 LAN 交付，扁平，与网卡相关；通常 48 bit，可随设备移动。
**IP 地址**：网络层，跨网络路由，层次化，与网络位置相关；便于路由聚合。
**ARP**：同一 LAN 内 IP 到 MAC 的解析；解决 IP 下一跳如何封装成链路层目的地址。
**ARP 过程**：请求广播 `FF:FF:FF:FF:FF:FF`；目标主机单播回复；发送方缓存映射，减少后续广播。
**ARP 原因**：即插即用，按需学习，无需手工配置全网映射；代价是广播和欺骗风险。
**跨子网转发**：IP 源/目的端到端不变；每跳 MAC 源/目的改变；主机先 ARP 默认网关 MAC。
**以太网帧**：preamble 同步、destination MAC、source MAC、type 解复用、data 载荷、CRC 检错。
**以太网服务**：无连接、不可靠；错帧丢弃，不回 ACK/NAK；可靠性通常由 TCP 等上层提供。
**现代以太网**：交换式、全双工、每链路独立冲突域；主机到交换机链路通常不再碰撞。
**交换机**：透明即插即用，自学习建立 MAC 表；主机无需配置交换机地址。
**自学习**：记录源 MAC 和入端口；表项有老化时间，适应主机移动。
**转发规则**：目的已知且不同端口则转发；同端口过滤；未知目的泛洪到除入端口外所有端口。
**交换机作用**：分割冲突域、支持并行通信；未知 MAC、ARP、广播仍可能扩散到整个 VLAN。

### VLAN、MPLS、数据中心、网页请求

**VLAN 原因**：限制广播范围，隔离部门/安全域，逻辑归属不受物理位置限制；提高可管理性和安全性。
**VLAN 划分**：基于端口、MAC、IP；端口 VLAN 简单常用，动态 VLAN 管理更复杂。
**VLAN 通信**：同 VLAN 二层转发；跨 VLAN 需要三层路由，就像不同子网之间通信。
**802.1Q**：trunk 携带 VLAN 标签；TPID 常见 `0x8100`，TCI 含 VLAN ID 和优先级；用于跨交换机识别 VLAN。
**802.1Q 注意**：插入标签后以太网帧内容改变，CRC 需要重新计算。
**MPLS**：固定长度标签转发，位于链路层和网络层之间的虚拟化机制；中间 LSR 可不查 IP 最长前缀。
**MPLS 头部**：20 bit label、Exp/流量类别、S 栈底、TTL；支持标签栈和 QoS 标记。
**MPLS 原因**：快速标签查找，流量工程，按源/业务走不同路径，预计算备用路径和快速重路由。
**数据中心挑战**：大规模并发、可靠性、负载均衡、高吞吐低时延、自动化管理；东西向流量巨大。
**数据中心结构**：边界路由器、聚合交换机、Top-of-Rack、服务器机架；多层拓扑提供冗余和扩展性。
**数据中心技术**：多路径负载均衡、SDN、ECN/DCTCP/DCQCN、RoCE、服务放置；目标是低时延高吞吐。
**网页请求全链路**：DHCP 配 IP/gateway/DNS；ARP 得网关 MAC；DNS 解析；TCP 握手；HTTP；IP 路由；以太网/交换机交付。
