# 存储器层次结构

### 为什么要设计存储器层次结构
SRAM 很快，但很贵，容量小，常用于 Cache。
DRAM 较慢，但容量较大，价格较低，常用于主存。
磁盘 / SSD 容量大、价格低，但访问速度远慢于内存。

寄存器
↓
L1 Cache
↓
L2 Cache
↓
L3 Cache
↓
主存 DRAM
↓
SSD / 磁盘

## 局部性原理——为什么存储器层次结构有效
1. 时间局部性
最近访问过的数据或者指令，很快可能被再次访问，例如for 循环指令

2. 空间局部性
如果访问了某个地址，那么它附近的地址也很可能马上被访问，例如数组。

## 基本概念
1. Cache Line / Cache Block
块是不同存储器层次之间传输数据的基本单位。
当CPU 访问一个字节，但是不在Cache中时，Cache可能需要从主存中一次取64个字节到Cache中。

2. Hit 命中
CPU要访问的数据已经在Cache中

3. Miss 缺失
CPU要访问的数据不在Cache中。

4. Miss Penalty
发生确实后，从低层存储器吧数据取到高层存储器所需的额外空间，成为缺失代价。
例如Cache Line从主存中读取数据，可能需要几十到几百个周期

5. SRAM（Static RAM） 静态随机访问存储器
速度快，不需要刷新

6. DRAM（Dynamic RAM） 动态随机访问存储器
需要周期性刷新，用电容中的电荷表示数据

- DDR DRAM （Double Data Rate）双倍数据传输

7. Flash Memory 闪存
易失性存储器， 比磁盘块， 比DRAM慢， 磁轭如次数有限，通过**损耗平衡 Wear leveling**来讲写入操作分散到不同物理块上，让所有块尽量均匀磨损。

## Cache
### 直接映射Cache
主存中的块号只能放到Cache中唯一的位置
```
Cache 块号 = 主存块号 % Cache 中的块数
```
例如 Cache 有 8 个块，主存块号 22：
```
22 % 8 = 6
```
所以主存块 22 只能放到 Cache 第 6 块。 但这样会经常容易发生冲突

### Cache中的地址分解
`Tag | Index | Offset`
- Offset 内部偏移：要访问的数据在块内部的偏移，如果一个块是16字节，需要4位offset
- Index： 用来选择Cache中某一行或者某一组的数据
- Tag：用来判断这一行中存放的是不是目标主存块，因为在直接映射Cache中，多个主存块肯呢个映射到同一个Cache为止，仅靠Index不够，需要靠Tag区分。
- Valid Bit有效位： Valid Bit=0 代表改行位空或者无效
- Dirty Bit脏位：`Dirty=1`代表Cache中国的数据被修改过，和主存中的不一样。

### Cache缺失处理
缺失情况：
- 指令 Cache 缺失：CPU 取不到下一条指令，需要等待指令块加载
- 数据 Cache 缺失：CPU 访问 load/store 数据失败，需要等待数据块加载。

### 写策略 Write-through 与 Write-back
1. Write-through
写Cache的同时，也写主存，Cache和主存始终一致，不存在脏位的问题。主存带宽压力大。

写缓冲Write-Buffer

CPU写了Cache后，把要写入主存的数据放入写缓存中，只有当缓冲满了，才CPU等待数据写入主存。

2. Write-back
写命中时只修改Cache，不立即修改主存。**等Cache块被替换时，才将修改过的内容写会主存**。
对于写频繁的程序来说，优势是显而易见的。

### 写缺失策略 Write Allocate 与 No Write Allocate
当上述写操作中，写命令没有命中时，有两种策略：
1. 写分配 Write Allocate
写缺失时，先把目标块从主存取入 Cache，然后再写 Cache。
**常与 写回 Write-back 搭配。**原因是：如果以后还会继续访问这个块，把它放进 Cache 是有价值的

2. 非写分配 / 绕过 Cache No Write Allocate
写缺失时，不把块加载到 Cache，而是直接写主存。
**常与 写直达 Write-through 搭配。**

*不管哪种写缺失策略，最终一定保证写命令可以正确执行。*

### Cache 性能指标
1. 平均存储器访问时间 AMAT（Average Memory Access Time）
```
AMAT = 命中时间 + 缺失率 × 缺失代价
```

2. Cache对CPI的影响
```
CPU周期 = 理想执行周期 + 存储器阻塞周期（Cache）
```
例如：
```
基本 CPI = 2
指令 Cache 缺失率 = 2%
数据 Cache 缺失率 = 4%
缺失代价 = 100 周期
load/store 指令比例 = 36%

指令缺失贡献 = 2% × 100 = 2
数据缺失贡献 = 36% × 4% × 100 = 1.44

实际 CPI = 2 + 2 + 1.44 = 5.44
```

### Cache 相联度
Cache 的相联度决定了一个主存块可以放在 Cache 的哪些位置。
1. 直接映射 Direct Mapped
每个主存块只能放在一个固定位置。
2. 全相联 Fully Associative
一个主存块可以放到Cache中的任何位置。
3. n 路组相联 n-way Set Associative
主存块先映射到某个组，然后可以放在该组内任意一路。
```
组号 = 主存块号 % Cache 组数
```

### 替换策略
当Cache某组已经满，又发生缺失时，需要选择一个旧块替换。
1. 直接映射
直接替换到主存应该存储在Cache中的位置。
2. LRU（Least Recently Used）：最近最少使用
原理：根据时间局部性，最近没用过的数据，将来可能也不太会用。
3. 随机替换 Random

### 多级Cache
```
CPU
↓
L1 Cache：最小、最快
↓
L2 Cache：较大、较慢
↓
L3 Cache：更大、更慢，可能多个核共享
↓
主存
```
因为 L1 每条指令几乎都会访问，命中时间非常关键。L1 Cache常分为指令Cache和数据Cache，这种结构叫Split Cache。
而 L2/L3 只有在 L1 缺失时才访问，所以可以稍慢，但要尽量减少主存访问。

### Cache缺失的来源
1. 强制缺失 Compulsory Miss / Cold Miss
第一次访问某个块时，Cache 中一定没有，所以必然缺失。也叫冷启动缺失。
2. 容量缺失 Capacity Miss
Cache 容量有限，程序工作集太大，导致之前用过的数据被替换。
解决方法：增大 Cache 容量；改进程序局部性。
3. 冲突缺失 Conflict Miss
多个主存块竞争同一个 Cache 位置或同一组，导致反复替换。主要出现在直接映射或低相联度 Cache 中。

## 虚拟存储器 Virtual Memory
**虚拟存储器把主存看作磁盘的 Cache**

每个程序看到的是自己的虚拟地址空间，而不是直接看到物理内存。
好处：

- 隔离进程：每个程序以为自己独占内存。
- 保护安全：程序不能随便访问别人的内存。
- 简化编程：程序使用连续虚拟地址，不必关心物理内存碎片。
- 扩展容量：程序可用地址空间可以大于实际物理内存。

### 页 Page
虚拟存储器中的块称为**页**。常见页大小为 `4KB`.

### 虚拟地址与物理地址
程序产生的是**虚拟地址**，而真正访问DRAM需要的是**物理地址**。
由**CPU和操作系统**共同完成地址转换。

虚拟地址通常分为`虚拟页号 VPN | 页内偏移 Offset`, 物理地址通常分为`物理页号 PPN | 页内偏移 Offset`, 页内偏移不变。

### 页表 Page Table
**页表是记录虚拟页到物理页映射关系的数据结构**。

**每个进程通常有自己的页表**。

1. 页表项
称为 **PTE Page Table Entry**
PTE中通常包含：
- 物理页号。
- 有效位。
- 访问权限。
- 引用位。
- 脏位。
- 页面是否在内存中。
- 如果不在内存中，它在磁盘交换区的位置。

页表可能很大，不适合完全放在 CPU 内部。

但如果每次访问内存前都要先访问页表，那么一次内存访问会变成两次内存访问，为了解决这个问题，需要TLB。

2. TLB（Translation Lookaside Buffer）
地址转换的Cache，常称为快表。作用就是**加速虚拟地址到物理地址的转换**。
```
CPU 产生虚拟地址
↓
查 TLB
↓
TLB 命中：快速得到物理页号
↓
访问 Cache / 主存
```
如果TLB缺失：
```
从内存中的页表读取 PTE
↓
把 PTE 放入 TLB
↓
重新进行地址转换
```
页表访问也有局部性。程序访问某个页面后，通常还会继续访问同一页或附近页，所以对应 PTE 可以缓存起来.

3. TLB 缺失与缺页的区别
- TLB 缺失表示页可能在内存中，但是对应的PTE不在TLB中，无法准确定位页的物理地址。这是需要查页表项PTE，把PTE加入TLB。
- 缺页 表示目标页不在物理内存中，需要操作系统从磁盘把页面读入内存。
**缺页代价远高于 TLB 缺失，可能需要数百万个 CPU 周期**。

### 缺页处理
缺页时，系统中发生了什么？
```
1. CPU发现页表项PTE无效
2. 触发异常，进入操作系统
3. OS 根据虚拟地址找到对应的PTE
4. OS 在磁盘中找到目标页
5. OS 选择一个物理页框存放目标页
6. 如果被替换页是脏页，先写回磁盘  ！！这一步与Cache和主存的关系一样
7. 从磁盘读入目标页
8. 更新页表
9. 重新执行指令
```
回想Cache中的Write-through 和Write-back操作，注意到**虚拟存储器通常都是用写回**，因为磁盘访问极慢。如果每次写内存都同步写磁盘，性能会崩溃

### 存储器保护
页表项PTE 还可以设置权限，例如只读，可写，可执行，用户可访问，仅内核态可访问等。
保证了：
1. 一个进行不能随意修改另一个进程的数据 ！！[重要]
2. 用户程序不能随意访问操作系统的内核！！

虚拟机的核心部分，把虚拟资源映射到真实物理资源。

## 可信性 Dependability
### 故障、错误与失效
存储系统需要可靠工作。
- 故障 Fault
硬件或组件出现问题。例如一个 DRAM 位单元损坏。

- 错误 Error
故障导致系统内部状态不正确。例如某一位数据从 0 变成 1。

- 失效 Failure
系统对外提供的服务不符合要求。例如程序读到了错误数据，导致崩溃。

### 一些可信性指标 
1. MTTF （Mean Time to Failure）平均无故障时间
！？随机过程！？
2. MTTR （Mean Time To Repair）平均修复时间
！？ 随机过程 ！？
3. MTBF （Mean Time Between Failures） 平均失效间隔时间
`MTBF = MTTF + MTTR`

### 可用性
`可用性 = MTTF / (MTTF + MTTR)`
减少故障发生或者加快故障修复。

## 多处理器 Cache 一致性
多核处理器中，不同的CPU核拥有自己独立的和共享的Cache，通常L1 Cache和L2 Cache是每个核自己独有的L3 Cache共享。

Cache 一致性的基本要求是： `读操作应该返回最新写入的值`

### 一致性协议
1. 监听协议 Smooping Protocal
每个Cache都监听总线上的读写操作，如果发现其他CPU对自己的缓存块进行了写操作，就react。
适合共享总线结构。

2. 目录协议 Directory Protocal
系统维护一个目录，记录每个块被哪些 Cache 缓存、处于什么状态。

适合大规模多处理器系统，因为总线监听在核心数多时不易扩展。

3. 无效化协议 Invalidation Protocal
当某个 CPU 要写一个共享块时：
它在总线上广播无效消息。其他 Cache 中对应块被置为无效。写者获得独占访问权。之后其他 CPU 再读这个块，会发生缺失，然后获得新值。

这种方法避免多个 Cache 同时保留同一个块的不同版本
